5. Рекурсивный запрос: поддерево от SC
Базовая часть: SELECT ... WHERE node_id = 'ST:SC' — начальный узел, depth = 0, path = node_id.

Рекурсивная часть: JOIN lab.geo_tree g ON g.parent_id = s.node_id — присоединяет детей к текущему узлу, depth + 1, path || ' -> ' || g.node_id.

Условие завершения: когда очередная итерация не добавляет новых строк (у текущих листьев нет детей).

Пример path:

text
ST:SC
ST:SC -> CT:SC:florianopolis
ST:SC -> CT:SC:joinville
6. Обратный рекурсивный запрос: предки города
Базовая часть: выбранный city-узел, depth = 0.

Рекурсивная часть: JOIN lab.geo_tree g ON g.node_id = a.parent_id — поднимается к родителю, пока не достигнет BR.

7. Количество потомков каждого штата
Рекурсивно строится транзитивное замыкание ancestor → descendant. Для каждого state-узла считается число потомков (вычитается 1 — сам узел).

8. Защита от цикла
Если в графе есть цикл (A → B → A), рекурсия зациклится. Защита — массив visited:

sql
WITH RECURSIVE safe AS (
    SELECT node_id, parent_id, ARRAY[node_id] AS visited
    FROM lab.geo_tree WHERE node_id = 'ST:SC'
    UNION ALL
    SELECT g.node_id, g.parent_id, s.visited || g.node_id
    FROM lab.geo_tree g
    JOIN safe s ON g.parent_id = s.node_id
    WHERE NOT g.node_id = ANY(s.visited)
)
SELECT * FROM safe;
Каждая итерация добавляет узел в массив. Если узел уже посещён — рекурсия останавливается.

Контрольные вопросы
1. Чем VIEW отличается от MATERIALIZED VIEW?
VIEW хранит только определение запроса и вычисляется при каждом обращении. MATERIALIZED VIEW физически хранит результат и требует REFRESH для обновления. Первое всегда актуально, но медленнее при частых запросах; второе быстро читается, но может быть устаревшим.

2. Что является условием завершения рекурсивного CTE?
Рекурсия останавливается, когда очередная итерация не добавляет новых строк (неподвижная точка). В терминах SQL: рекурсивная часть возвращает 0 строк.

3. Как рекурсивный запрос связан с транзитивным замыканием отношения?
Рекурсивный CTE вычисляет транзитивное замыкание отношения parent → child. Базовая часть задаёт начальные узлы, рекурсивная добавляет достижимые узлы шаг за шагом. Результат — все узлы, достижимые из начального за любое число шагов.
