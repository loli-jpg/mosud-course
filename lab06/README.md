## Задача
Найти заказы, у которых сумма платежей превышает сумму price + freight_value по позициям.

## Основное решение (п.1)
- **Скалярные подзапросы** — `(SELECT SUM(payment_value) ...)` и `(SELECT SUM(price + freight_value) ...)` возвращают по одному числу для каждого заказа.
- **EXISTS** — отсекаем заказы без платежей или без позиций, иначе сравнение с NULL даёт NULL (не TRUE).
- Оба подзапроса **коррелированные** — зависят от `o.order_id` текущей строки.

## Альтернатива (п.2)
CTE с предварительной агрегацией:
- `pay` — сумма платежей по заказу.
- `items` — сумма price+freight по заказу.

Затем JOIN по `order_id`. Одна строка на заказ → нет размножения.

## Эквивалентность (п.3)
- `main EXCEPT alt` = **0**
- `alt EXCEPT main` = **0**

Обе реализации дают одинаковый результат.

## ANY / ALL (п.4–5)
- **ANY** — «хотя бы один платёж > 1000»: `1000 < ANY (SELECT payment_value ...)`.
- **ALL** — «все позиции дороже 100»: `100 < ALL (SELECT price ...)`. Добавлен `EXISTS`, чтобы не сработало vacuous truth на пустом множестве позиций.

## Контрольные вопросы

**1.** Коррелированный подзапрос ссылается на столбцы внешнего запроса и логически выполняется для каждой строки. Независимый — вычисляется один раз, результат используется для всех строк.

**2.** EXISTS удобнее IN при наличии NULL: IN с NULL может вернуть NULL вместо TRUE/FALSE, а EXISTS всегда даёт TRUE/FALSE. Также EXISTS быстрее останавливается (при первом совпадении), а IN материализует весь список.

**3.** Скалярный подзапрос стоит в контексте, где ожидается одно значение. Если вернёт больше строк — PostgreSQL бросит ошибку `more than one row returned by a subquery used as an expression`.
