## Эквивалентность разбиения предиката
Предикат `review_score <= 2 AND review_comment_message IS NOT NULL` разбит на две последовательные выборки. Результаты запросов 1, 2, 3 совпадают — 10890 строк. Это подтверждает свойство коммутативности выборки: порядок фильтров не влияет на результат.

## Эквивалентность при раннем проецировании
В запросе 3 проекция применяется раньше фильтрации. Результат тот же — 10890 строк. Это показывает, что при оптимизации можно уменьшать объём данных на ранних шагах, если столбцы, нужные для фильтра, сохраняются.

## Дубликаты в проекции
Проекция в реляционной алгебре устраняет дубликаты, потому что результат — множество. В SQL `SELECT` оставляет дубликаты.

- Всего строк: 10890
- Уникальных комбинаций (order_id, review_score, review_comment_message): 10890
- SELECT vs SELECT DISTINCT: 10890 vs 10890

## Вывод о дубликатах
Числа совпали — в проекции дубликатов нет. Это объясняется тем, что поле `order_id` в `order_reviews` практически уникально для каждой комбинации (order_id, review_score, comment), а `review_comment_message` содержит длинный текст, который редко повторяется точно. Поэтому `SELECT` и `SELECT DISTINCT` дают одинаковый результат — 10890 строк.

В общем случае проекция в SQL может давать дубликаты (если убрать `order_id` из проекции — например, оставить только `review_score` и `review_comment_message` — вероятно, появятся повторяющиеся пары). Для полной эквивалентности математической проекции нужен `SELECT DISTINCT`.

## Контрольные вопросы

### 1. Какие свойства выборки позволяют менять порядок нескольких фильтров?
Коммутативность: σ_p(σ_q(R)) = σ_q(σ_p(R)). Порядок применения фильтров не важен, если оба предиката применяются к одному отношению.

### 2. Почему проекция в математической модели устраняет повторяющиеся кортежи, а SELECT в SQL — нет?
В реляционной модели отношение — это множество, поэтому дубликаты недопустимы. SQL исторически работает с мультимножествами (по соображениям производительности), поэтому `SELECT` без `DISTINCT` сохраняет повторы.

### 3. Что означает замкнутость операций реляционной алгебры?
Результат любой операции реляционной алгебры — тоже отношение. Это позволяет комбинировать операции в произвольные выражения (деревья), потому что выход одной операции подходит как вход для другой.
